## Findings

### P1 · The Mayor's route and the current Special contract block structured authoring

The bundled Mayor passes hours, paths, and a combat delegate to `follow_time_script`. Route opcodes choose the speeches, posture changes, and the hard-coded `gate` argument. A designer can rearrange existing opcodes by editing the expression. Changing a line or naming another door requires Python. `Special.from_json` passes normalized fields to the dataclass constructor, which rejects both proposed fields, `payload` and `timedRoute`. Publishing either field today can fail startup or cause staged reload to reject the snapshot. Ship support for reading and executing the new shape before writing migrated records. [Special parser](../../src/area/Special.py#L27) · [Startup and staged reload](../../src/server/FetchAndRegisterMixin.py#L51)

### P2 · Duplicate assignments can bind different behaviors at startup and reload

The registry enforces identity by document ID. Two distinct IDs for the same `(areaId, mobVnum)` are accepted. Initial binding takes the first match in the registry, while reload builds a map that keeps the last match. An in-memory probe with two different records for the same pair reproduced different choices. A designer create or import could cause this if it inserts a new document for an already assigned mobile. Enforce one assignment per pair for startup, staged reload, and service writes. Update the existing assignment when a designer changes its behavior. The bundled snapshot has 411 unique assignments. [Initial binding](../../src/area/SpecialRegistry.py#L41) · [Reload bindings](../../src/area/SpecialService.py#L31)

## Contract and rollout

1. **Read before writing.** Update the Python parser, content-service read/write/export models, and designer editor for additive fields. Use an explicit typed entry point for each migrated behavior. Require exactly one executable branch per migrated record and clear the legacy expression in the same write. Keep existing scripts readable and allow editing each type through its matching controls. Use one canonical assignment validation for initial load and reload. Validate typed references, message keys, and delegate cycles before a candidate becomes active.
2. **Use the existing message channels and live delivery rules.** Normalize keys with the same convention as `GamePayload` so `greetAtHome` resolves to `greet_at_home`. Give the executing context access to its definition's payload, including the callee's payload during delegation. Reuse `DisplayUtil` for recipient-specific act tokens and posture checks. Validate the allowed tokens per action in the editor. Route yells and door feedback through their command paths. Carry forward the current local versus distant whistle audiences when resolving its three keys. [Payload model](../../src/game/GamePayload.py#L25) · [Act rendering](../../src/util/DisplayUtil.py#L75) · [Delegate execution context](../../src/mobile/MobileHandler.py#L233)
3. **Prove one complete edit-and-publish flow with the Mayor.** Save a revised line and door target through the designer, read the same ID and typed fields through the service, and confirm export and import preserve them. Activate through restart for the first release, or expose an operator path that publishes and rebinds on the world loop if hot activation is in scope. Show the chosen activation policy in the designer. Fetch and validate a replacement before publication. Test that an invalid candidate leaves the previous bindings available, that definitions with the same name resolve independently by ID, and that active routes honor the published-version policy. Replay both complete routes and compare pulse-by-pulse actions, messages, recipients, and door results against the existing tests. [Staged reload](../../src/server/FetchAndRegisterMixin.py#L62) · [World-loop ownership](../references/Architecture.md) · [Mayor regressions](../../tests/test_rom24_report_fixes.py#L221)

This limits how much schema, UI, and runtime behavior has to change together for each publish.

## Verification and limits

The collection CLI verified the shape, family counts, and representative scripts. A compact query using its loader verified unique IDs and assignment pairs, the two unassigned behaviors, and identical scripts within each family. In-memory probes reproduced the parser rejection and duplicate-assignment selection. All 53 tests passed across `test_mobile_special_binding`, `test_mobile_pulse`, `test_restored_mobile_specials`, and `test_rom24_report_fixes` in isolated processes. Async fixtures used a socketless event loop in the Windows sandbox.

The designer and content-service checkouts were unavailable in the workspace and nearby project locations checked. The proposed field names, editor controls, and activation flow need verification against those projects. This update changes the report only.
