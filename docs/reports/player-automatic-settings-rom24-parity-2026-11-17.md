# ROM24 parity review of player automatic settings

This review covers `autolist` and the six `auto*` toggles it reports. It checks command dispatch, flag mutation, feedback, and the immediate effect of `autoexit` on room views. Earlier reviews covered auto-assist, corpse actions, and room visibility in other contexts. Combat and corpse action rules are outside this review. [Earlier combat review](archive/fight-c-rom24-parity-2026-10-18.md) · [Earlier room display review](archive/repository-rom24-parity-2026-11-03-current.md)

## Confirmed defect

### The six toggles report success while switched without changing a setting

Switch into a mobile and type `autoassist`. ROM24 returns silently because the current character is an NPC. Springs also skips the flag mutation, but then reads the mobile's raw act bits to choose a player-facing confirmation. An NPC with only `ACT_IS_NPC` produces “Autoassist removed.” An NPC with `ACT_SCAVENGER` produces “You will now assist when needed.” in the same situation because `ACT_SCAVENGER` and `PLR_AUTOASSIST` use the same bit value. Neither message reflects a change to the original player or the mobile. The other five toggle handlers follow the same pattern. `autolist` itself returns silently in both implementations while switched. The public-interpreter probe used a connection bound to the switched body. With only `ACT_IS_NPC`, all six commands sent their disabled message. Adding `ACT_SCAVENGER`, `ACT_AGGRESSIVE`, `ACT_STAY_AREA`, and `ACT_WIMPY` changed the messages for `autoassist`, `autosac`, `autogold`, and `autosplit` to enabled. The original player's flags and the mobile's flags were identical before and after each group of commands. The seven bundled commands run at level zero and `POS_DEAD`, and their role metadata allows dispatch while switched. The handlers determine the NPC behavior. ## Verified differences with unresolved intent

### Switched room arrival and explicit look read different auto-exit flags

ROM24 routes ordinary movement through `look auto`. Both bare `look` and `look auto` require a non-NPC current body before printing automatic exits. Springs explicitly reads the original player's flag when rendering arrival, while bare `look` reads the current body's raw act bits. With `autoexit` enabled on the controller and an ordinary mobile body, arrival shows exits and bare `look` omits them. In a synthetic fixture with bit 8 set on the mobile and the controller's setting disabled, the behavior flips. Bit 8 is unassigned in the bundled NPC act enum. The controller preference for arrival is explicit in the code, but the intended policy across the two views is unconfirmed. ### Abbreviations follow the existing command lookup difference

ROM24 dispatches `auto` to `autolist`, `autoex` to `autoexit`, and `autoloo` to `autoloot` by table order. Springs resolves exact names and authored shortcuts. These records have no shortcuts for the tested inputs, and the interpreter probes returned “Huh?” for all three. An earlier review already recorded the general lookup policy as unresolved. ## Matching paths and validation

For an unswitched player, each full toggle ignores trailing input, changes only its own act bit, and sends the corresponding enable or disable message. The six rows in `autolist` follow ROM24's order. The display also agrees for compact, prompt, combine, corpse looting, summoning, and followers in both tested states. The probe preserved unrelated act bits and verified that settings survive a Python character serialization round trip. ROM24 saves its act mask as flags and restores it with `fread_flag`. Springs uses numeric character status fields.
