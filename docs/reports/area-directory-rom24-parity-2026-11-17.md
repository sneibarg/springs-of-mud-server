# ROM24 parity review of the area directory

This review covers `areas` from loaded area metadata through argument handling, ordering, and row rendering. The earlier pager review compared delivery of long output. This review covers the directory contents before delivery. [Earlier pager review](scroll-pager-rom24-parity-2026-11-17.md)

## Verified differences

### A 39-character column can cut off an authored area name

ROM24 loads each area's authored credit string and passes it to `%-39s`. This specifies a minimum width, so the credit is printed in full even if it exceeds 39 characters. Springs constructs the label from metadata and slices it to 39 characters before padding. No combined label in the current 49-area snapshot exceeds the limit. With a valid synthetic area named `Amber Gate and the Forgotten Court of the First Kings`, the public command printed only `[15 25] Builder: Amber Gate and the For`. The next column began immediately after `For`, leaving the rest of the area name invisible. The renderer also drops a populated level range when the author string is blank. A test area with `10 20` and a blank author appeared only as `Crystal Woods`. ROM24 prints whatever level text the builder put in credits, independently of whether those credits contain an author. This second edge was reproduced with synthetic metadata. All shipped Springs entries had authors. ### Midgaard and Ofcol display numeric level bounds

ROM24 prints the literal `All` credit for the two areas. In the Springs snapshot, both records also contain `All` as their suggested level range. The production area factory changes it to `1 50` before the directory handler reads it. The rendered entries are `[1 50] Diku: Midgaard` and `[1 50] Alfa: Ofcol`. That makes a categorical recommendation appear to have an upper bound. It does not itself enforce a travel restriction. Limbo keeps its `None` category in both, with different punctuation around it. Intent for turning `All` into a numeric recommendation is unconfirmed. ### The two columns use different ordering rules

ROM24 appends areas in boot-file order. It puts the first half of that list down the left column and the rest down the right. The local boot list contains 52 files, of which 48 start with an `AREA` record. The first row pairs the credits from `immort.are` and `hitower.are`. Springs sorts the loaded registry by case-insensitive area name and writes consecutive entries across each row. With the bundled snapshot it starts with Arachnos and Astral/Githyanki, and ends with Wyvern's Tower alone. The difference in map size reflects the two content snapshots. The sort and row-pairing difference comes from the runtime. Whether the alphabetical, row-first layout is a deliberate replacement remains unconfirmed. ## Matching paths and validation

The level-zero command can run from `POS_DEAD` in both implementations. Both reject trailing arguments with the same message, and a whitespace-only remainder lists the areas. The exact command and `ar`, `are`, and `area` all produced the same Springs output. ROM24 accepts those inputs through table-order prefix matching. A directory with an odd count has a final row with no second entry.
