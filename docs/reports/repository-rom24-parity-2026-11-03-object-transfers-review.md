# ROM24 parity review of object transfers and shop interactions

November 3, 2026. Reviewed the current Springs working tree based on `40949b8` against the local ROM24 C checkout. The latest combat aftermath and profile fixes are present.

## Findings

| Priority | Trigger and consequence | Evidence |
| --- | --- | --- |
| P2 | **Ordinary coin gifts silently change denominations.** ROM24 debits and credits exactly the denomination named by the giver. Springs converts both wallets to silver-equivalent totals and then normalizes them into gold and silver. A gift of 200 silver to an empty wallet gave the receiver 2 gold and 0 silver in the runtime probe. This can prevent the receiver from immediately spending or splitting the silver they were told they received. | [ROM24 act_obj.c](C:/Users/scott/PycharmProjects/PyRom/Rom24/src/act_obj.c:708) · [Object.py](../../src/interp/commands/Object.py#L1470) · [Wallet helpers](../../src/interp/commands/Object.py#L2692) |
| P2 | **Money changers accept too little silver and can return the wrong denomination.** ROM24 first computes whole gold for silver-to-gold exchange. With 100 silver the result is zero gold, so a changer who sees the giver declines and refunds all 100 silver. Springs accepts the exchange, keeps five silver, and returns 95. Conversely, giving two gold should return 190 silver. The Python probe received one gold and 90 silver. These branches need separate denomination handling, including ROM's payout float adjustments. | [ROM24 act_obj.c](C:/Users/scott/PycharmProjects/PyRom/Rom24/src/act_obj.c:727) · [Exchange calculation](../../src/interp/commands/Object.py#L1394) · [Exchange payout](../../src/interp/commands/Object.py#L1516) |
| P2 | **Single-item drops omit the room audience.** ROM24 announces a successful single drop to eligible bystanders, including the dissolve notice for a melt-on-drop item. Springs creates room text but supplies no targets on the single-item path. The standard object emitter sends room text only when a target list is present. A probe with a witness in the room produced the expected text and an empty audience. Bulk and money drops use separate audience handling. | [ROM24 act_obj.c](C:/Users/scott/PycharmProjects/PyRom/Rom24/src/act_obj.c:588) · [Object.py](../../src/interp/commands/Object.py#L991) · [PlayerHandler.py](../../src/player/PlayerHandler.py#L917) |
| P3 | **Giving an item echoes the bystander line to the giver.** ROM24's TO_NOTVICT excludes both participants. Springs uses a room helper that excludes only the receiver, so a registered giver gets a direct acknowledgment and their own third-person action line. The probe placed both participants in the room registry and confirmed the giver was the sole room target. | [ROM24 act_obj.c](C:/Users/scott/PycharmProjects/PyRom/Rom24/src/act_obj.c:816) · [ROM24 comm.c](C:/Users/scott/PycharmProjects/PyRom/Rom24/src/comm.c:2483) · [Object.py](../../src/interp/commands/Object.py#L1438) · [Room.py](../../src/area/Room.py#L231) |
